# Pass A1: adversarial audit of the branch that added the HTTP transport

Audited tree: `a2be42a` (branch `http-transport`, one commit on `ed9b40f`), whole module, with the new code
(`http.go`, `http_client.go`, `sse.go`, `client.go`, `app/mcpd/http.go`, `example/http`) first. Date 2026-11-09.
Method: the house audit method (`handbook/audits.md`): four report-only auditors, one skeptic per candidate, fixes,
re-validation. This file is a record of what was found and decided; it is not updated when the code moves.

Labels: **verified** (run, or the exact lines read, by the auditor or skeptic named), **reported** (an agent says it; the
record did not re-run it), **inferred**. Everything attributed to an auditor or skeptic below is *reported* by that agent
unless the line says the recorder ran it.

## How it differed from the handbook

- The auditors (A simplify, B dedup, C correctness+security, D docs) were fresh agents with no build context: the tree,
  the docs, the handbook and a shell. The harness refused A, C and D permission to write their findings files, so those
  three returned their findings as text and B's file was the only one saved. The candidates the skeptics saw are
  condensed from the reports, in the finding form, into a scratch file that is not part of the repository.
- The scratch file the skeptics read held the 38 candidates selected for a vote (C-1..16, D-1..12, B-1..7, A-3, A-4, A-8). Six of
  them were not sent: D-1 and D-2 (the same defects as C-7 and C-10), B-6, and A-3, A-4, A-8 (judged not worth a vote). The
  remaining 32 were. Doc-only skeptics ran no code, so some have no scratch directory.
- **One skeptic vote per candidate**, not two to four, and no arbiter. 32 candidates were put to a skeptic; the other 27 are
  accounted for below as "not voted" with the reason (two of them, D-1 and D-2, are the same defects as C-7 and C-10 and were
  covered by those votes).
- **The fixes were written by the build session, not by fixers in worktrees**, one finding at a time, test first. Most
  fixes touch the same three files, which worktrees would have made conflict. The fix-skeptic pass is recorded at the
  end of this file.
- Skeptics ran on darwin/arm64 only; nothing here was run on Linux.

## Held for the owner, resolved

The first pass held five items because each changes the behaviour or a guarantee of released code, and recorded a
recommendation for each. The owner then said to take the recommendations, fix and verify. Each was done as written, test first
(red on the old code, green on the new), then mutation-checked by the recorder. This part was not put to fresh skeptics.

- **H1 (C-9) Queued-request bytes: done.** `Options.MaxQueuedBytes`, default `8 * MaxMessageBytes` (64 MiB at the default),
  counted over the method, id and params of requests that are queued or running, per session. Past it a request gets the
  "overloaded" error. A request is always admitted when the session holds nothing else, so a budget below `MaxMessageBytes` cannot
  make a large message impossible (not in the recommendation; the alternative made a small setting a way to lock a session out).
  Tests: `TestQueuedBytesBudget`, `TestQueuedBytesBudgetAdmitsALoneOversizedRequest`. Not changed: the HTTP transport's own inbound
  queue (64 POST bodies, each up to `MaxMessageBytes`) sits before the read loop; it drains into the budget quickly, and its
  bound (inferred: 512 MiB per session at the default, if the read loop stalls) was not measured.
- **H2 (C-14) `Broadcast`: done, with one change to the recommendation.** The recommendation was to close a session that does not
  drain. Closing at the first full queue would also close a healthy session that is merely busy (replies share the queue), so a
  session whose queue is full is given a grace period (5 s, unexported `defaultBroadcastGrace`) and closed only if it still cannot
  take the frame; sessions that are waiting are waited on together, so a `Broadcast` costs at most one grace period, and the rest
  are served at once. `NotifyResourceUpdated` uses the same path. `Session.Notify` still blocks. Tests:
  `TestBroadcastDropsAPeerThatStoppedReading` (a healthy and a non-reading peer, `WriteTimeout` unset),
  `TestBroadcastWaitsOnStalledPeersTogether`. The grace is not configurable; that is a one-line option if an owner wants it.
- **H3 (C-8) `HTTPOptions.MaxSessionsPerIdentity`: done.** Default 0 (off), counted under the registry lock, answered 429, released
  when the session closes. Sessions with an empty identity are not counted, so it does nothing unless `Identify` is set. Tests:
  `TestHTTPMaxSessionsPerIdentity`, `TestHTTPPerIdentitySlotReleasedOnExpiry`. mcpd has no `Identify`, so no flag was added.
- **H4 (D-3) mcpd on macOS/BSD: done.** `MaxConnsPerUID > 0` no longer makes `admit` demand credentials, so the default `mcpd -socket`
  serves connections off Linux and the per-UID cap is simply not counted there. `RequirePeerCred`, `AllowUID` and `AllowGID` still
  fail closed. Tests: `TestAdmitWithoutCredsOnlyFailsClosedForAnExplicitPolicy`, `TestServePerUIDCapAloneServes` (the latter
  failed on the old code with a broken pipe on this machine). `TestMaxConnsPerUID` (Linux only) was not run.
- **H5 (B-2) `jsonrpc` version: done.** `wireMessage.checkVersion` runs in `handleFrame` and `handleBatch` for every message
  kind; the error carries the request's id for a request and null otherwise (so an error is never addressed to a response). The
  Client stays lenient. Tests: `TestBadVersion*` (a notification, a request, a batch, a response). Residual: a frame this package rejects is answered with an error that has a null id, and the server answers such an error
in turn with another invalid-request error (verified: a scratch test sent `{"id":null,"error":...}` and got `-32600` with a null
id back). So two of these servers wired to each other would trade errors; that second step is inferred, not run. It was already
true for any invalid frame, and the change widens it by the bad-version cases.

Mutation checks of these five (a deliberate break in a scratch copy; KILLED means a test failed): 14 mutants. Three survived at first:
the response's rejection id was untested, the claim that stalled peers are waited on together was untested (both now have tests),
and a redundant guard in the per-identity check was an equivalent mutant (the guard was removed). All 14 were then KILLED.

## Fix-skeptic pass

Five fresh skeptics attacked commit `bb4f851` (the fixes), one per cluster, told to default to FAILED. Results, and what was done
about each (reported by the skeptics; the recorder re-ran the tests after every change):

- **C-2, C-10, C-13, C-16: FIXED-VERIFIED.** The new tests fail on the old code. The skeptic wrote an extra round-trip test for 12 header-framed
  sizes around the 64 KiB chunk boundary and found no fault. Non-blocking notes: the README listed `HandshakeTimeout` as a deadline
  below the framer (now worded as a timer); a bare `Close` can cut off a healthy write in progress (now in the CHANGELOG).
- **C-1, C-7, B-7: FIXED-VERIFIED.** No leak path for the reserved ids (2000 dropped POSTs left at most the Session's own queue bound
  and cancelling them cleared all), no way for the handshake timer to kill a Ready session. Two items acted on: the reserved-id
  behaviour is now documented in the README and architecture doc. Two residuals not acted on, both inferred and not reproduced: a
  cancel that frees the id a few microseconds before the Session has suppressed a reply it had already queued, and a
  `notifications/initialized` POSTed within microseconds of the handshake deadline.
- **C-3, C-12, B-1: FIXED-VERIFIED, with a leak.** Under a stalled peer each timed-out call left two goroutines (403 after 200
  calls) and the "skip a write whose caller gave up" check had no test. Fixed: the write lock became a context-aware
  semaphore, the cancel notification got a 5s bound, and `TestClientCallsGivingUpDoNotAccumulateGoroutines` and
  `TestClientDoesNotSendRequestsItsCallersGaveUpOn` were added. That change was found, by running the suite repeatedly, to have
  introduced a race on a test knob (read now at spawn) and an interaction with the cancel notification that the first
  version missed (a write abandoned for its context must still send the cancel).
- **C-5, C-11: FIXED-VERIFIED. C-4: FIX-INCOMPLETE. C-6: FIX-REGRESSES (interop).** C-4: the abort of a cancelled call's POST ran
  inside the write path, so a server that stalled the cancel POST too kept the slots. Fixed: the Client aborts the POST before it
  queues the cancellation, cancellations are asynchronous and draw on a budget of their own, and a test
  (`TestHTTPClientAbortsCancelledCallsEvenIfTheServerStallsTheCancel`) stalls both. C-6: a 200 or 201 with no body to a
  notification made `Initialize` fail; now any empty 2xx is accepted. C-11: the GET-stream loop retried a 3xx forever; it now
  stops, and the CHANGELOG says so.
- **C-15, the documentation, this record: FIX-INCOMPLETE, then corrected.** The read limit itself (as opposed to the check after
  it) had no test: `readBounded` was split out and tested with an endless reader. The `HTTPHandler` comment still gave two
  revisions (D-13); two references in this file pointed at sections that did not exist; A-11 was missing from the ledger; one claim
  about the Session was overstated. All corrected here. The skeptic verified D-3, D-5..D-12 and D-15, and ran the documented
  example curl sequence end to end.

Mutation checks the recorder ran (a mutant is a deliberate break of the fix in a scratch copy; KILLED means a test failed): each fix
above was broken in at least one way and a test failed. Four mutants survived at first (a C-1 routing mutant, two C-4 mutants, and
a C-4 slot-sharing mutant introduced by the follow-up); each pointed at a weak test, which was strengthened until the mutant was
KILLED. The mcpd `read_file` fix was mutated by replacing `readRegular` with `os.ReadFile` (both tests failed) and by removing
the `io.LimitReader` (the `readBounded` test failed). The recorder did not mutate every line of every fix; the set is the ones
named in the commit messages and test names.
